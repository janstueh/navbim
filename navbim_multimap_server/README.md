# navbim_multimap_server

The `navbim_multimap_server` package extends `nav2_map_server` with support for serving collections of per-room occupancy grid maps organized by floor. It is the primary map source for the navbim stack, enabling `navbim_multi_costmap_2d` to initialize a separate costmap for each room.

## Overview

Standard `nav2_map_server` serves a single occupancy grid map. BIM-based multi-floor navigation requires one occupancy map per room so that the room planner can check for collisions within each room independently. The `navbim_multimap_server` manages this collection: it loads all per-room maps at startup, publishes each map on its own topic, and broadcasts the full room index on the `environments` topic so that `navbim_multi_costmap_2d` can subscribe to the right maps.

Maps are organized into environments. Each environment corresponds to one building floor and contains the per-room maps for that floor. Optionally, a per-floor aggregate map can also be included in an environment (used for floor-level path smoothing).

The map files (`.yaml` + `.png`) are generated offline from the IFC model by `navbim_nav_model_gen`.

## Node: `multimap_server`

The `multimap_server` node is based on `nav2_map_server` and is launched as a lifecycle node.

### Parameters

| Parameter | Type | Default | Description |
|---|---|---|---|
| `environments_file` | string | `""` | Path to the environments YAML file listing all rooms per floor; loaded automatically on activation |

### Services

| Service | Type | Description |
|---|---|---|
| `load_environments` | `navbim_msgs/srv/LoadEnvironments` | Load an environments file at runtime |
| `load_map` | `navbim_msgs/srv/LoadMultiMap` | Load an additional map collection at runtime |
| `dump_map` | `navbim_msgs/srv/DumpMultiMap` | Save the current map collection to disk |
| `dump_environments` | `std_srvs/srv/Trigger` | Clear all loaded environments and maps |
| `maps/<floor>/<room>/static_map` | `nav_msgs/srv/GetMap` | Retrieve the occupancy grid for a specific room (one service per loaded map) |

### Topics Published

| Topic | Type | Description |
|---|---|---|
| `environments` | `navbim_msgs/msg/Environments` | Full room index (all floors and their maps); published once on activation with transient local QoS |
| `maps/<floor>/<room>/map` | `nav_msgs/msg/OccupancyGrid` | Occupancy grid for a specific room (one topic per loaded map) |
| `maps/<floor>/<room>/map_metadata` | `nav_msgs/msg/MapMetaData` | Map metadata for a specific room (one topic per loaded map) |

## Environments File Format

The environments file (generated by `navbim_nav_model_gen` as `<ifc_name>.yaml`) lists all floors and their maps:

```yaml
Ground_Floor:
  global_frame: "ifc"
  maps:
    Room_001: Ground_Floor/Room_001/Room_001.yaml
    Room_002: Ground_Floor/Room_002/Room_002.yaml
    Ground_Floor: Ground_Floor/Ground_Floor.yaml   # optional aggregate floor map

First_Floor:
  global_frame: "ifc"
  maps:
    Room_101: First_Floor/Room_101/Room_101.yaml
    Room_102: First_Floor/Room_102/Room_102.yaml
```

Each map entry is a standard Nav2 occupancy grid YAML file pointing to a `.png` image:

```yaml
image: Room_001.png
resolution: 0.05
origin: [12.4, 5.1, 0.0]
occupied_thresh: 0.65
free_thresh: 0.196
negate: 0
```

## Related Packages

- `nav2_map_server`: upstream package that this package is based on
- `navbim_nav_model_gen`: generates the per-room map files and environments YAML consumed by this package
- `navbim_multi_costmap_2d`: subscribes to `environments` and the per-room map topics to initialize room costmaps
