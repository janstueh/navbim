# navbim_multi_costmap_2d

The `navbim_multi_costmap_2d` package extends `nav2_costmap_2d` with support for maintaining separate 2D costmaps for each room in a multi-floor building. It provides the `MultiCostmap2DROS` node, which replaces the standard `Costmap2DROS` node in the navbim stack.

## Overview

Standard Nav2 navigation uses a single global costmap for path planning. BIM-based multi-floor navigation requires a separate costmap per room so that the room planner (`navbim_gpp_bim`) can plan collision-free paths within each room independently. `navbim_multi_costmap_2d` manages this collection of per-room costmaps and activates or deactivates them in response to the robot's current room.

Each room costmap consists of:
- A **static layer** initialized from the room's occupancy grid map (generated by `navbim_nav_model_gen`)
- An **inflation layer** that inflates obstacle costs outward: cells within half the robot width are marked with infinite cost (inscribed zone); beyond that, costs decay exponentially with configurable `inflation_radius` and `cost_scaling_factor`

For path smoothing, per-room cost maps are aggregated into per-floor cost maps. The `navbim_smoother` uses these floor-level cost maps to prevent smoothing into obstacles at room boundaries.

## Node: `multi_costmap_2d`

`MultiCostmap2DROS` is a `nav2_util::LifecycleNode` that extends `Costmap2DROS`. It overrides the activation and deactivation lifecycle to manage the per-room costmap collection.

### Topics Published

| Topic | Type | Description |
|---|---|---|
| `maps/<env>/<map>/map` | `nav_msgs/msg/OccupancyGrid` | Inflated costmap for a specific room (one topic per room; mirrors the `navbim_multimap_server` map topic naming) |
| `costmap/<floor_name>/aggregated` | `nav_msgs/msg/OccupancyGrid` | Aggregated per-floor costmap for floor-level path smoothing (transient local QoS; one topic per floor) |

### Topics Subscribed

| Topic | Type | Description |
|---|---|---|
| `/environments` | `navbim_msgs/msg/Environments` | Floor map environments from `navbim_multimap_server`; used to initialize per-room static costmap layers (transient local QoS) |
| `/current_room` | `navbim_msgs/msg/CurrentRoom` | Current room from `navbim_room_tracker`; used to activate the matching costmap |

### Services Used

| Service | Type | Description |
|---|---|---|
| `/topomap_server/get_min_z` | `navbim_msgs/srv/GetMinZ` | Query the minimum Z coordinate for room height calculations during costmap initialization |

## Costmap Filters

The `navbim_multi_costmap_2d` package inherits the costmap filter infrastructure from `nav2_costmap_2d`. Costmap filters can be applied to individual room costmaps in the same way as in the standard Nav2 costmap.

See the [nav2_costmap_2d documentation](https://docs.nav2.org/configuration/packages/configuring-costmaps.html) for general costmap parameter descriptions.

## Related Packages

- `nav2_costmap_2d`: upstream package that this package is based on
- `navbim_multimap_server`: provides the per-floor occupancy grid maps used to initialize static layers
- `navbim_room_tracker`: publishes the `current_room` topic consumed by this package
- `navbim_gpp_bim`: uses the per-room costmaps for metric path planning
